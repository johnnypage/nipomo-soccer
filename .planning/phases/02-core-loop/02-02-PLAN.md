**Step 2: Add POST /api/submissions endpoint.**

```typescript
app.post("/api/submissions", requireFamily, async (req, res) => {
  try {
    const parseResult = submitSchema.safeParse(req.body);
    if (!parseResult.success) {
      return res.status(400).json({ error: "Invalid submission data" });
    }

    const { kidId, challengeId, weekNumber, type, cloudinaryId, cloudinaryUrl, thumbnailUrl } = parseResult.data;

    // Verify kid belongs to this family (T-02-04)
    const [kid] = await db.select().from(kids).where(
      and(eq(kids.id, kidId), eq(kids.familyId, req.session.familyId!))
    );
    if (!kid) return res.status(404).json({ error: "Kid not found" });

    // Verify challenge exists
    const [challenge] = await db.select().from(challenges).where(eq(challenges.id, challengeId));
    if (!challenge) return res.status(404).json({ error: "Challenge not found" });

    // Daily cap check per D-04, D-15: max 1 skill + 1 fitness per child per day, globally
    const today = new Date();
    const dayStart = startOfDay(today);
    const dayEnd = endOfDay(today);

    const [existing] = await db
      .select({ count: count() })
      .from(submissions)
      .where(and(
        eq(submissions.kidId, kidId),
        eq(submissions.type, type),
        gte(submissions.submittedAt, dayStart),
        lt(submissions.submittedAt, dayEnd)
      ));

    if (existing.count >= 1) {
      return res.status(409).json({ error: "Already submitted today. Come back tomorrow!" });
    }

    // Insert submission -- points defaults to 1 per PTS-01
    const [submission] = await db.insert(submissions).values({
      kidId, challengeId, familyId: req.session.familyId!,
      weekNumber, type, cloudinaryId, cloudinaryUrl, thumbnailUrl,
    }).returning();

    // Get updated total points for this kid (PTS-03 cumulative)
    const [total] = await db
      .select({ totalPoints: sql<number>`cast(coalesce(sum(${submissions.points}), 0) as int)` })
      .from(submissions)
      .where(eq(submissions.kidId, kidId));

    res.json({ success: true, points: 1, totalPoints: total.totalPoints });
  } catch (error) {
    console.error("Submission error:", error);
    res.status(500).json({ error: "Failed to record submission" });
  }
});
```

app.get("/api/submissions/status", requireFamily, async (req, res) => {
  try {
    const kidId = req.query.kidId as string;
    if (!kidId) return res.status(400).json({ error: "kidId query parameter required" });

    // Verify kid belongs to this family
    const [kid] = await db.select().from(kids).where(
      and(eq(kids.id, kidId), eq(kids.familyId, req.session.familyId!))
    );
    if (!kid) return res.status(404).json({ error: "Kid not found" });

    const today = new Date();
    const dayStart = startOfDay(today);
    const dayEnd = endOfDay(today);

    // Today's submissions by type (for daily cap display)
    const todaySubmissions = await db.select({
      type: submissions.type,
      weekNumber: submissions.weekNumber,
    }).from(submissions).where(and(
      eq(submissions.kidId, kidId),
      gte(submissions.submittedAt, dayStart),
      lt(submissions.submittedAt, dayEnd),
    ));

    // All submissions for this kid (for past week status indicators)
    const allSubmissions = await db.select({
      weekNumber: submissions.weekNumber,
      type: submissions.type,

      .select({ totalPoints: sql<number>`cast(coalesce(sum(${submissions.points}), 0) as int)` })

    res.json({
      todaySubmissions,

      totalPoints: total.totalPoints,

**Step 2: Add GET /api/leaderboard endpoint (public, no auth).**

Per D-08: public endpoint, no login required. Per PRIV-02/LDR-06: uses kids.displayName (already "First L." format). Per PRIV-03: NEVER returns cloudinaryUrl or cloudinaryId. Per LDR-04: returns rank, displayName, ageTrack, totalPoints, isRegistered. Per LDR-05: isRegistered from families table for NSC Player badge.

```typescript
app.get("/api/leaderboard", async (_req, res) => {
  try {
    const leaderboard = await db
      .select({
        kidId: kids.id,
        displayName: kids.displayName,
        ageTrack: kids.ageTrack,
        totalPoints: sql<number>`cast(coalesce(sum(${submissions.points}), 0) as int)`,
        isRegistered: families.isRegistered,
      })
      .from(submissions)
      .innerJoin(kids, eq(submissions.kidId, kids.id))
      .innerJoin(families, eq(kids.familyId, families.id))
      .groupBy(kids.id, kids.displayName, kids.ageTrack, families.isRegistered)
      .orderBy(desc(sql`sum(${submissions.points})`));

    // Add rank numbers
    const ranked = leaderboard.map((entry, index) => ({
      rank: index + 1,
      ...entry,
    }));

    // Get aggregate stats for hero section
    const [stats] = await db
      .select({
        totalSubmissions: count(),
        totalPlayers: sql<number>`cast(count(distinct ${submissions.kidId}) as int)`,
      })
      .from(submissions);

    res.json({
      leaderboard: ranked,
      stats: {
        totalSubmissions: stats?.totalSubmissions ?? 0,
        totalPlayers: stats?.totalPlayers ?? 0,
      },
    });
  } catch (error) {
    console.error("Leaderboard error:", error);
    res.status(500).json({ error: "Failed to load leaderboard" });
  }
});
```

IMPORTANT: The leaderboard response shape is `{ leaderboard: Array<{ rank, kidId, displayName, ageTrack, totalPoints, isRegistered }>, stats: { totalSubmissions, totalPlayers } }`. There is NO cloudinaryUrl, cloudinaryId, or full name in this response. This is the privacy boundary (PRIV-03).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /api/submissions | Untrusted Cloudinary metadata from browser; user claims kid ownership |
| client -> POST /api/video-bonus | User claims video bonus; no proof of watching |
| public -> GET /api/leaderboard | Public endpoint; must not leak private data |
| client -> GET /api/submissions/status | Authenticated user queries another kid's data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Spoofing | POST /api/submissions | accept | Unsigned Cloudinary uploads mean someone could POST fake cloudinary IDs. Acceptable risk at community-challenge scale (1 point per submission, not high-value). Server validates kid ownership and daily cap. |
| T-02-04 | Elevation of Privilege | POST /api/submissions | mitigate | Verify kid.familyId === req.session.familyId before INSERT. Prevents submitting for another family's child. |
| T-02-05 | Tampering | POST /api/submissions | mitigate | Server-side daily cap: COUNT submissions by kid_id + type + DATE(submitted_at). Returns 409 on duplicate. Client-side state is display-only per D-04. |
| T-02-06 | Information Disclosure | GET /api/leaderboard | mitigate | Never return cloudinaryUrl or cloudinaryId in response. Only return kids.displayName (already "First L." format from Phase 1). |
| T-02-07 | Information Disclosure | GET /api/submissions/status | mitigate | requireFamily middleware + verify kid.familyId matches session. Cannot query another family's kid status. |
| T-02-08 | Tampering | POST /api/video-bonus | mitigate | Server enforces 1 video bonus per kid per week (D-06). Checks challenge.videoUrl exists (D-07). Honor system on "watching" is accepted design per D-05. |
| T-02-09 | Denial of Service | POST /api/submissions | accept | Rate limiting not in scope for Phase 2. At community scale (~50 families), abuse risk is minimal. Express inherits Replit Autoscale request limits. |
