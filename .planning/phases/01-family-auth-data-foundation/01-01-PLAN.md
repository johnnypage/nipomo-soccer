```typescript
// Trust proxy for secure cookies behind Replit's HTTPS proxy
app.set("trust proxy", 1);

// Session middleware -- PostgreSQL-backed sessions for family auth
const PGStore = connectPgSimple(session);
const sessionPool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
});

app.use(session({
  store: new PGStore({
    pool: sessionPool,
    tableName: "sessions",
    createTableIfMissing: true,
  }),
  secret: process.env.SESSION_SECRET || "dev-session-secret-change-in-production",
  resave: false,
  saveUninitialized: false,
  cookie: {
    maxAge: 30 * 24 * 60 * 60 * 1000, // 30 days
    httpOnly: true,
    secure: process.env.NODE_ENV === "production",
    sameSite: "lax",
  },
}));
```

Per RESEARCH Pitfall 5: trust proxy set to 1 for Replit's HTTPS proxy.
Per RESEARCH Pitfall 2: secure flag conditional on NODE_ENV for local dev compatibility.

Note: A separate pg.Pool is created for connect-pg-simple rather than importing from db.ts, because db.ts exports a Drizzle instance, not the raw pool. This is the approach recommended in RESEARCH.md.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Express API | All user input (email, kid data) crosses this boundary as untrusted JSON |
| Express -> PostgreSQL | Schema definitions control what data reaches the database |
| Session cookie -> Express | httpOnly cookie carries session ID; Express validates server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | shared/schema.ts | mitigate | Drizzle ORM parameterized queries prevent SQL injection. No raw SQL in schema definitions. |
| T-01-02 | Tampering | server/index.ts session config | mitigate | httpOnly: true prevents JS access to session cookie. sameSite: "lax" prevents CSRF on POST. secure: true in production prevents cookie theft over HTTP. |
| T-01-03 | Information Disclosure | server/index.ts session secret | mitigate | SESSION_SECRET loaded from env var. Fallback dev secret only used locally. User setup note: generate a strong secret for production. |
| T-01-04 | Spoofing | server/index.ts session fixation | accept | express-session generates new session IDs. Plan 02 will call req.session.regenerate() after magic link verification for full session fixation protection. |
| T-01-05 | Information Disclosure | shared/schema.ts kids.displayName | mitigate | Per D-06, displayName stores only "First L." (first name + last initial). Full last name is stored but never exposed to public-facing queries (enforced in Plan 02/03 route handlers). |
</threat_model>
