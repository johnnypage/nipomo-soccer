function getAgeTrack(birthdate: Date): "littlekicks" | "starter" | "advanced" {
  const age = differenceInYears(new Date(), birthdate);
  if (age >= 4 && age <= 6) return "littlekicks";
  if (age >= 7 && age <= 10) return "starter";
  if (age >= 11 && age <= 18) return "advanced";
  throw new Error(`Age ${age} is outside the challenge range (4-18)`);
}

function getDisplayName(firstName: string, lastName: string): string {
  return `${firstName} ${lastName.charAt(0).toUpperCase()}.`;
}

**POST /api/auth/signup** -- Per D-01 Step 1, AUTH-01, PRIV-01:
- Parse body with signupSchema.safeParse(req.body)

- Normalize email: trim + lowercase

- Token expiry: `new Date(Date.now() + 15 * 60 * 1000)` (15 minutes)
- Update family row with magicToken and tokenExpiresAt
- Call sendMagicLink(email, token)
- Return `{ success: true, message: "Check your email for a login link" }` -- same response whether email exists or not (prevents email enumeration, per RESEARCH threat model)

**POST /api/auth/login** -- Resend magic link for existing accounts:
- Parse body: `z.object({ email: z.string().email() }).safeParse(req.body)`
- Normalize email: trim + lowercase
- Look up family by email
- If not found: return same success response (prevents enumeration)
- Generate new token, update family, send magic link
- Return `{ success: true, message: "Check your email for a login link" }`

**GET /api/auth/verify** -- Per D-01 Step 2, D-10:
- Extract token from query string: `req.query.token as string`
- If no token, return 400
- Look up family where magicToken = token AND tokenExpiresAt > now

- Invalidate token: set magicToken to null, tokenExpiresAt to null
- Regenerate session (session fixation protection): `req.session.regenerate()` callback sets `req.session.familyId = family.id` then saves
- Redirect to `/challenge` (per D-10)

**GET /api/auth/me** -- Per D-12, AUTH-03:
- If no req.session.familyId, return 401
- Query family by id
- Query kids where familyId = family.id, ordered by createdAt
- Return `{ family: { id, email, name, isRegistered, createdAt }, kids: [...] }`

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | POST /api/auth/signup | mitigate | 32-byte random token (2^256 entropy). Rate limiting should be added if abuse detected (not in phase 1 scope, acceptable for ~50 family scale). |
| T-02-02 | Spoofing | GET /api/auth/verify | mitigate | Token invalidated immediately after use (set to null). 15-minute expiry. Session regenerated after verification (prevents session fixation). |
| T-02-03 | Information Disclosure | POST /api/auth/signup | mitigate | Same response for existing and non-existing emails ("Check your email for a login link") prevents email enumeration. |
| T-02-04 | Elevation of Privilege | POST /api/kids, PATCH /api/kids/:id, DELETE /api/kids/:id | mitigate | All kid queries include `WHERE familyId = req.session.familyId`. Kids cannot be accessed across family boundaries. |
| T-02-05 | Tampering | POST /api/auth/signup, POST /api/kids | mitigate | All POST bodies validated with Zod .safeParse() before any database operations. Invalid input returns 400. |
| T-02-06 | Tampering | POST /api/kids birthdate | mitigate | Birthdate validated as YYYY-MM-DD string by Zod regex, then parsed to Date. Age track computed server-side (not user-provided). Out-of-range ages (< 4 or > 18) rejected with 400. |
| T-02-07 | Replay | GET /api/auth/verify | mitigate | Token set to null immediately after successful verification. Replaying the same link returns "expired" error. |
| T-02-08 | Information Disclosure | GET /api/auth/me | mitigate | Only returns family data for the authenticated session. Kids scoped to familyId. Never returns magicToken or tokenExpiresAt. |
| T-02-09 | Denial of Service | POST /api/auth/signup SendGrid | accept | SendGrid has its own rate limiting. At ~50 family scale, abuse risk is low. If needed in future: add per-email rate limiting (not phase 1 scope). |
